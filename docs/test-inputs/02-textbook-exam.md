# 02. 교재·기출 — 소프트웨어 개발 원칙

- 목적: 설명 글 + 기출 문제 형태가 섞인 원문에서 핵심만 정확히 뽑는지 확인
- 확인할 완료 조건: 3-2, 3-3, 3-4(한 면 30초 이내), **3-5(원문에 없는 내용 0개)**
- 원문 출처: Flip 테스트용으로 직접 작성한 글 (저작권 걱정 없음)

## 원문 (이것만 복사)

```
[소프트웨어 개발 원칙]

KISS는 "Keep It Simple, Stupid"의 줄임말로, 설계를 가능한 한 단순하게 유지하라는 원칙이다. 복잡한 구조는 이해하기 어렵고 오류가 숨기 쉽기 때문이다.

DRY는 "Don't Repeat Yourself"의 줄임말로, 같은 지식이나 로직을 여러 곳에 반복해서 쓰지 말라는 원칙이다. 같은 코드가 여러 곳에 있으면 수정할 때 한 곳을 빠뜨려 오류가 생기기 쉽다.

YAGNI는 "You Aren't Gonna Need It"의 줄임말로, 지금 필요하지 않은 기능은 미리 만들지 말라는 원칙이다. 미래를 예상해 만든 기능은 실제로 쓰이지 않는 경우가 많고, 유지보수 부담만 늘린다.

SOLID는 객체지향 설계의 다섯 가지 원칙의 앞 글자를 딴 것이다. 그중 단일 책임 원칙(SRP)은 하나의 모듈이 하나의 책임만 가져야 한다는 원칙이다.

[예상 문제]
다음 중 지금 필요하지 않은 기능을 미리 만들지 말라는 원칙은?
① KISS ② DRY ③ YAGNI ④ SRP
정답: ③
```

## 체크 포인트

- [ ] 카드 수가 1~20장 사이인가? (5~8장 안팎이 자연스러움)
- [ ] 각 면이 3문장 이하이고, 30초 안에 읽히는가?
- [ ] **함정 ①**: SOLID의 나머지 4개 원칙(개방-폐쇄, 리스코프 치환 등)이 카드에 나오면 → 원문에 없음 → 3-5 실패
- [ ] **함정 ②**: DRY를 만든 사람·책 이름 같은 배경 지식이 붙으면 → 원문에 없음 → 3-5 실패
- [ ] [예상 문제]가 카드로 바뀌었을 때 정답(③ YAGNI)이 맞게 들어갔는가?

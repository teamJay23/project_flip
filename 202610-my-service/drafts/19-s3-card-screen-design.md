# 19. 3단계 카드 화면(C 학습 화면) 디자인 정리

- 작성: 2026-10-24, 마케터 / 기준: PRD v1.5 기능 8·9·10 (완료 조건 4-1, 4-2, 5-1~5-3, 6-1~6-3), 기능 11·12의 버튼 위치(7-1, 8-1)
- 참고: `06-design-reference-research.md`(Anki, Quizlet, Flippy, 클래스카드), `my-feature.html`(읽기만), `trialnerror/index.html`(옛 프로토타입, 읽기만)
- 이 문서는 **디자인 제안**이다. 코드는 고치지 않았다. 구현은 dev, 결정은 팀이 한다.

> **한 줄 요약**: 카드는 화면 가운데 큰 판 하나, 탭하면 Y축으로 뒤집히는 연출(움직임 줄이기 설정이면 바로 바뀜)을 추천한다. 안다/모른다 버튼은 **카드 바로 아래 왼쪽 끝·오른쪽 끝**에 두는 안을 추천하지만, PRD의 "카드 왼쪽 바깥/오른쪽 바깥"을 이렇게 읽어도 되는지 **팀 확인이 필요하다.** 그리고 `my-feature.html`의 `:root`에는 아직 `--know`, `--review`, `--back` 변수가 **없다**(옛 프로토타입에만 있음).

## 1. 3단계 범위 (만드는 것 / 만들지 않는 것)

| 구분 | 내용 | PRD 근거 |
|---|---|---|
| 만든다 | 카드 만들기가 끝나면 추가 조작 없이 첫 카드 앞면 | 4-1 |
| 만든다 | 1라운드는 만들어진 순서대로, 같은 질문 두 번 안 나옴 | 4-2 |
| 만든다 | 처음엔 앞면(질문)만 보임, 글자가 넘치거나 잘리지 않음 | 5-1, 5-3 |
| 만든다 | 카드 탭 → 뒷면(답). **뒤집기만** 하고 다음 카드로 안 넘어감 | 6-1, 6-2 |
| 만든다 | 답 글자가 넘치거나 잘리지 않음 | 6-3 |
| 자리만 | "← 알고 있음" / "모름 · 애매 →" 버튼 (동작은 4단계, 탭 먼저) | 7-1, 8-1 |
| 범위 밖 | 진행도(몇 번째 카드, 남은 수), 라운드 바뀜 표시, 스와이프, [이전]/[다음(스킵)], 즐겨찾기, 카드 스타일 바꾸기 | 기능 13, 14, 11·12 2차, 3번 "하지 않는 것" |
| 범위 밖 (이후) | 새로고침·다른 앱 다녀와도 유지(4-3), 탭 닫으면 초기화(4-4) | 9번 구현 순서 "이후" |

- 5-2("다음 카드도 앞면부터")는 다음 카드로 넘어가는 4단계에서 확인된다. 3단계에서는 "카드가 바뀔 때 앞면 상태로 시작"하도록 만들어 두기만 하면 된다.

## 3. 화면 배치

### 3-1. 세로 배치 (위 → 아래)

```
┌──────────────────────────┐  ← env(safe-area-inset-top) + 20px
│ (빈 공간 또는 작은 앱 이름) │
│ ┌──────────────────────┐ │
│ │                      │ │
│ │   카드 (탭 영역 전체)   │ │  ← 남은 높이를 채움 (flex:1)
│ │   질문 글자 18px 이상   │ │
│ │                      │ │
│ └──────────────────────┘ │
│ [← 알고 있음]   [모름 · 애매 →] │  ← 엄지 영역, 높이 52px 정도
└──────────────────────────┘  ← env(safe-area-inset-bottom) + 20px
```

- 지금 `.screen`(높이 `100dvh`, 안전 영역 패딩, 최대 너비 480px, 좌우 16px)을 **그대로** 쓴다. 학습 화면도 `<main class="screen">` 하나로 만들면 iOS 안전 영역·`100dvh` 처리가 깨지지 않는다.
- 위쪽에 진행도·라운드를 넣지 않는다(범위 밖). 비워 두거나 "Flip" 글자 정도만.

### 3-2. 버튼 위치 — PRD "카드 왼쪽 바깥 / 오른쪽 바깥"을 어떻게 읽을까 (팀 확인 필요)

화면 너비 375px 기준 계산: 좌우 여백 16px씩 빼면 쓸 수 있는 너비는 **343px**.

| 안 | 모양 | 카드 너비 (375px 기준) | 장점 | 단점 |
|---|---|---|---|---|
| ① 카드 옆 (세로 띠) | 카드 왼쪽에 세로 버튼, 오른쪽에 세로 버튼 | 버튼 각 56px + 간격 8px×2 → 카드 약 **215px** | PRD 글자 그대로 "왼쪽·오른쪽 바깥" | 카드가 좁아 한 면 3문장이 길게 늘어진다(한 줄 약 11자). 버튼이 화면 가운데 높이라 한 손 엄지가 닿기 어렵다. 글자를 세로로 써야 함 |
| **② 카드 바로 아래 좌우 끝 (추천)** | 카드 밑에 한 줄, 왼쪽 끝 "← 알고 있음", 오른쪽 끝 "모름 · 애매 →" | 카드 **343px** 전체 | 카드가 넓어 3문장이 잘 들어간다. 엄지 영역. 화살표(←, →)가 방향을 말해 줘서 나중 스와이프 방향과도 맞다 | "카드 **바깥**"은 맞지만 "카드 **옆**"은 아니다 → PRD 해석 확인 필요 |
| ③ 카드 아래쪽 모서리에 반쯤 걸치기 | 버튼 반은 카드 위, 반은 밖 | 343px | 카드와 버튼이 한 덩어리로 보인다 | 버튼이 카드에 겹쳐 **카드 탭(뒤집기)과 버튼 탭이 헷갈린다** → 6-2 위험 |

- **추천: ②.** 06 조사 때도 같은 제안을 했다. PRD 7-1·8-1의 "카드 왼쪽 바깥"을 "카드 밖, 왼쪽 편"으로 읽으면 ②도 맞다. 이 해석이 괜찮은지는 4단계 전에 **팀(필요하면 강사님) 확인**.
- 두 버튼 사이에는 빈 공간을 둔다(가운데 버튼 없음 = [다음] 버튼이 없다는 것과 맞음).
- 누르는 영역: 높이 **44px 이상**(52px 제안), 너비는 각 버튼 글자 + 좌우 16px.

### 3-3. 3단계에서 버튼은 어떻게 보일까

| 방법 | 장점 | 단점 |
|---|---|---|
| (가) 자리와 모양만 그리고, 눌러도 아무 일 없음 | 4단계 때 배치가 바뀌지 않아 카드 크기 확인(5-3, 6-3)을 미리 정확히 할 수 있다 | 휴대폰으로 확인하는 사람이 "고장"으로 볼 수 있다 |
| (나) 3단계에선 숨기고 4단계에서 보이기 | 헷갈림 없음 | 4단계에서 버튼이 생기면 카드 높이가 줄어 5-3·6-3을 다시 확인해야 한다 |

- **추천: (가).** 대신 3단계 확인 체크리스트(6번)에 "버튼은 아직 동작하지 않음(4단계)"이라고 적어 둔다.

## 4. 카드 모양

| 항목 | 제안 | 이유 |
|---|---|---|
| 앞면 | 바탕 `--paper`, 글자 `--ink` | 입력창과 같은 종이 느낌. 대비 14.2 : 1 |
| 뒷면 | 바탕 `--back`, 글자 `--amber` | 옛 프로토타입과 같음. 앞/뒤가 색만으로 바로 구분됨. 대비 8.8 : 1 |
| 앞/뒤 작은 표시 (선택) | 카드 왼쪽 위에 작게 "질문" / "답" (`--ink-soft` / `--amber` 흐리게) | 색을 잘 구분하지 못하는 사람도 앞뒤를 안다. 진행도가 아니므로 범위 안. 넣을지는 팀 결정 |
| 글자 | Pretendard, **18px 이상**, 줄 간격 1.6, 가운데 정렬 대신 **왼쪽 정렬** 추천 | 3문장짜리 답은 가운데 정렬이면 줄마다 시작점이 달라 읽기 힘들다 |
| 모서리 | 둥근 모서리 16~18px | `.input`(16px), `.fail-box`(18px)와 맞춤 |
| 크기 | 너비 343px(375 화면) ~ 398px(430 화면), 높이는 버튼 줄을 뺀 남은 높이(`flex:1`) | 가장 작은 화면(375×667, iPhone SE 크기)에서 카드 높이 약 450~520px (위쪽 제목을 넣느냐에 따라 다름, 휴대폰에서 확인 필요) |

### 4-1. 글자가 넘치지 않을까 (5-3, 6-3)

- 대략 계산: 카드 안쪽 너비 약 300px, 18px 한글 → 한 줄 약 16자. 한 면 3문장 ≈ 150자 → 약 10줄 × 29px ≈ **290px**. 카드 높이(약 450px 이상) 안에 들어간다.
- 그래도 영어 긴 단어·긴 숫자는 한 줄을 넘칠 수 있다 → `overflow-wrap:anywhere`(긴 단어를 줄 끝에서 끊어 주는 설정) 제안.
- 정말 긴 면이 오면 **카드 안에서 스크롤**되게 할지, 글자를 줄일지 정해야 한다. "잘리지 않고 끝까지 보인다"를 지키려면 글자가 숨는 `overflow:hidden`은 쓰지 않는다. 확인은 `docs/test-inputs/`로 만든 카드 중 **가장 긴 면**으로 한다.

### 4-2. 색 대비 확인 (스크립트로 계산, WCAG 기준 4.5 : 1 이상이면 일반 글자 OK)

| 조합 | 대비 | 판정 |
|---|---|---|
| `--ink` 글자 / `--paper` 바탕 (앞면) | 14.2 | 좋음 |
| `--amber` 글자 / `--back` 바탕 (뒷면) | 8.8 | 좋음 |
| `--ink-soft` / `--paper` (작은 표시) | 5.41 | 좋음 |
| `--know` 글자 / `--bg-1` 배경 (테두리 버튼) | 7.49 | 좋음 |
| `--review` 글자 / `--bg-1` 배경 (테두리 버튼) | 5.37 | 좋음 |
| `--review` 글자 / `--bg-2` 배경 | **4.27** | 기준 아래 (배경 그라데이션의 밝은 쪽이 화면 위쪽이라 버튼이 아래에 있으면 괜찮음) |
| `--ink` 글자 / `--know` 바탕 (채운 버튼) | 6.68 | 좋음 |
| `--ink` 글자 / `--review` 바탕 (채운 버튼) | 4.79 | 좋음 |
| `--paper` 글자 / `--review` 바탕 | **2.96** | 나쁨 → 쓰지 말 것 |

- 버튼 제안: **채운 버튼**(바탕 `--know` / `--review`, 글자 `--ink`, 굵게 16~17px). [카드 만들기] 버튼(`.submit`, 바탕 `--amber` + 글자 `--ink`)과 같은 방식이라 앱 전체가 맞는다.

## 5. 뒤집기 연출 (3안)

| 안 | 어떻게 | 장점 | 단점 |
|---|---|---|---|
| **A. 3D Y축 회전 (추천)** | 카드가 세로축을 중심으로 0.4초 정도 돌아 뒷면이 나옴. 옛 프로토타입 CSS(`perspective`, `rotateY(180deg)`, `backface-visibility:hidden`)를 그대로 가져올 수 있음 | "카드를 뒤집는다"는 앱 이름(Flip)과 딱 맞음. 이미 만들어 본 코드가 있음 | 앞·뒤 두 면을 겹쳐 두어야 해서 **두 면 중 긴 쪽에 높이를 맞춰야** 함. iOS Safari에서 `-webkit-backface-visibility`를 같이 써야 뒷면이 비쳐 보이지 않음(확인 필요) |
| B. 바로 바뀌며 흐려졌다 나타남 (crossfade) | 앞면이 0.2초 동안 흐려지고 뒷면이 나타남 | 가장 단순. 두 면 높이 문제 없음. 멀미 걱정 없음 | "뒤집기" 느낌이 약함 |
| C. 납작해졌다 펴짐 (가로 크기 0 → 1) | 카드가 가로로 접혔다가 뒷면으로 펴짐 (2D) | 3D 없이도 뒤집는 느낌. iOS 문제 적음 | 중간에 글자가 찌그러져 보임. 코드가 A보다 조금 더 복잡 |

- **추천: A**, 그리고 휴대폰의 "동작 줄이기(움직임 줄이기)" 설정이 켜져 있으면 **B 또는 바로 바뀜**으로. `my-feature.html`의 로딩 원도 이미 `prefers-reduced-motion`으로 멈추므로 같은 규칙을 따르는 것이다.
- 시간은 0.3~0.5초. 너무 길면 "30초 안에 읽기"의 흐름을 끊는다.
- 뒤집는 중에 또 탭하면? 돌아가는 중이어도 **상태(앞/뒤)만 바뀌게** 두면 된다. 다음 카드로 넘어가는 일은 없다(6-2).

## 6. 탭 동작 세부

| 항목 | 제안 | 이유 |
|---|---|---|
| 탭 영역 | 카드 **전체** (Anki 방식) | 작은 버튼을 찾을 필요가 없다 |
| 뒷면에서 다시 탭 | **앞면으로 돌아감 (토글)** | PRD 7번 "만들면서 확인할 것"의 기본값 제안. 옛 프로토타입도 토글. 휴대폰에서 써 보고 팀이 정함 |
| 두 번 빨리 탭 | 앞→뒤→앞. 카드는 그대로 | 6-2 |
| 확대 막기 | 카드에 `touch-action: manipulation` | iOS에서 두 번 탭이 화면 확대로 잡히는 것과, 탭 반응이 늦어지는 것을 막는다 |
| 접근성 | 카드를 `<button>`(또는 `role="button"`)으로, `aria-label="카드 뒤집기"`, 지금 면을 `aria-live`로 읽어 줌 | 화면 읽기 기능 사용자도 뒤집을 수 있다. 실패 안내의 `role="alertdialog"`와 같은 생각 |
| 탭 안내 문구 (선택) | 첫 카드 아래 작게 "카드를 누르면 답이 보여요" | 처음 쓰는 사람용. PRD에 없는 문구라 넣을지 팀 결정. 진행도는 아니므로 범위 안 |
| 버튼과 카드 사이 | 간격 12px 이상 | 버튼을 누르려다 카드를 누르는 실수(또는 반대)를 줄인다 |

## 1. 길이 구분 기준 (이 표에서만 쓰는 가정)

PRD에는 "짧음/보통/김" 구분이 없다. 표를 만들려고 아래처럼 **가정**했다. 팀이 바꿔도 된다.

| 구분 | 한글이 주인 글 (띄어쓰기 제외 글자 수) | 영어가 주인 글 (단어 수) | 왜 이렇게 나눴나 |
|---|---|---|---|
| 짧음 | 10 ~ 300자 | 5 ~ 60단어 | 메모·단어장 정도. 카드 1~10장 예상 |
| 보통 | 301 ~ 1,500자 | 61 ~ 400단어 | 교재 한 단원, 짧은 기사 |
| 김 | 1,501 ~ 5,000자 | 401 ~ 2,000단어 | 긴 기사·보고서. 20장으로 다 못 담을 수 있음(PRD 7번 "어느 부분으로 만들지") |

- 세는 법은 v1.5 기능 3을 따른다. 띄어쓰기로 나눈 단어 중 **한글이 든 단어가 알파벳만 있는 단어보다 같거나 많으면** 한글이 주인 글로 보고 글자 수로 센다. 아니면 단어 수로 센다. 숫자·기호만 있는 단어는 판단에서 뺀다.
- `my-feature.html`의 `measure()`는 위 규칙과 **거의 같지만 한 곳이 다르다.** 한글 단어와 영어 단어가 **둘 다 0개**인 글(숫자·기호만 있는 글)이 그렇다.
  - PRD 문장대로 하면 "0 = 0, 같다" → 글자 수로 센다.
  - 지금 코드(`korean > 0 && korean >= english`)는 단어 수로 센다.
  - 두 방식의 결과가 반대로 나오는 예시 (직접 계산함, v2.1):

| 예시 | PRD대로 (글자 수, 띄어쓰기 제외) | 지금 코드 (단어 수) |
|---|---|---|
| `1 2 3 4 5` | 5자 < 10자 → **막힘** | 5단어 ≥ 5단어 → **통과** (AI까지 감) |
| `12345 67890` | 10자 ≥ 10자 → **통과** (AI까지 감) | 2단어 < 5단어 → **막힘** |
| (참고) `1234 5678 9012 3456 7890` | 20자 → 통과 | 5단어 → 통과 |

  - 마지막 줄(v2의 예전 예시)은 두 방식 모두 통과해서 차이가 드러나지 않는다. 대신 AI까지 가는 숫자 글이므로 4-a(카드 0장 → 원문 문제) 후보로 남겨 둔다.
  - 어느 쪽이 맞는지는 팀이 정한다 (5번 질문 5, 시험 원문 F-18).

## 3. 표2 — 기록 형식과 기존 샘플

**기록 형식 (새 샘플도 이 칸을 채운다)**

`id | 종류 | 언어 | 글자 수 | 출처 | 원문(앞 30자만) | 기대 결과 | 원문 속 숫자·이름·날짜 (이것 말고 나오면 실패) | 체크 포인트(함정)`

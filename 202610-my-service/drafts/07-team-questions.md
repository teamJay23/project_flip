## A. 시작 전에 꼭 정할 것

### 질문 1. API 키를 어디에 숨길까?
- **쉬운 설명:** API 키 = AI 서비스를 쓸 수 있게 해 주는 비밀번호입니다. HTML 파일은 누구나 내용을 볼 수 있어서 키를 넣으면 안 됩니다. 키를 대신 들고 있다가 AI를 불러 줄 "중간 다리"가 필요합니다.
  - (a) 구글 Apps Script: 팀이 이미 `Code.gs`로 써 본 방식
  - (b) Vercel 서버 함수: 배포하는 곳과 한곳에 두는 방식. 설치할 것이 많음
  - (c) 사용자가 자기 키를 입력: 직장인에게 키를 발급받으라고 해야 함
- **추천: (a) Apps Script** — *강사님 방식과 다를 수 있음*
- **이유:** 이미 해 본 방식이라 새로 배울 것이 가장 적고, 무료이며 설치가 없습니다. 앱 화면은 HTML 하나 그대로라서 "단일 HTML" 규칙과도 맞습니다.

### 질문 2. PRD의 ".env에 키 보관" 문구를 고칠까?
- **쉬운 설명:** PRD 6-1과 7-d에는 "키를 `.env` 파일에 둔다"고 적혀 있습니다. 1번에서 (a)를 고르면 키는 `.env`가 아니라 Apps Script 안의 비밀 메모장(스크립트 속성)에 들어갑니다. 문서와 실제가 달라집니다.
- **추천: 고친다.** (1번에서 (a)를 고를 때)
- **이유:** 문서와 실제가 다르면 나중에 팀원이 헷갈립니다. 7-d 확인 방법도 "스크립트 속성의 키를 일부러 틀리게 바꿔 본다"로 바꿉니다.

### 질문 3. 어떤 AI를 쓸까?
- **쉬운 설명:** PRD v1.5에 이미 Gemini가 적혀 있습니다. Gemini 안에서도 모델이 여러 개입니다. 2.5 Flash-Lite는 싸고 빠르고, 2.5 Flash는 조금 더 똑똑하지만 비쌉니다.
- **추천: Gemini로 시작. 2.5 Flash-Lite를 먼저 시험하고, 카드 품질 검사(3-5 "원문만 근거")를 통과하지 못하면 2.5 Flash로 바꾼다.** — *강사님 방식과 다를 수 있음*
- **이유:** PRD와 맞고, 무료로 시작할 수 있습니다. 더 싼 모델이 통과하면 그걸 쓰는 것이 가장 단순합니다.
- **결정 변경 (2026-10-27 admin): 처음부터 `gemini-3.5-flash-lite`로 시험한다.** 2.5 모델은 새 프로젝트에 막혀 있다("예전에 써 본 사용자에게만" 접근 허용). 3.5 Flash-Lite는 Google이 새 프로젝트에 권하는 안정판이고 무료 등급이 있다.

### 질문 4. 개발하는 동안 무료 등급만 쓸까?
- **쉬운 설명:** 무료 등급은 돈이 안 드는 대신, 보낸 글을 Google이 AI 개선에 쓰고 사람이 읽을 수도 있습니다. 결제 카드를 연결하지 않으면 최악의 경우에도 "무료 한도가 끝남"일 뿐, 돈이 나가지 않습니다.
- **추천: 무료 등급만 쓴다. 단, 공개해도 되는 테스트 원문(`docs/test-inputs/`)만 넣는다.**
- **이유:** 개발 단계에서는 돈이 들지 않는 것이 가장 안전합니다. 테스트 원문에는 비밀이 없으니 데이터 조건도 문제가 되지 않습니다.

### 질문 6. 카드 생성 코드를 지금 `Code.gs`에 합칠까, 따로 만들까?
- **쉬운 설명:** 지금 `Code.gs`는 구글 시트에 저장하는 시험용 코드입니다. 여기에 AI 카드 생성 코드를 같이 넣을지, 새 Apps Script 프로젝트를 하나 더 만들지 정해야 합니다.
- **추천: 새 프로젝트로 따로 만든다.**
- **이유:** 한 파일이 한 가지 일만 하면 고장 났을 때 원인을 찾기 쉽습니다(역할 나누기). 저장 기능은 7·8단계이므로, 그때 합칠지 다시 정하면 됩니다.

### 질문 12. 휴대폰에서 어떻게 열고, 앱 파일은 어디에 만들까?
- **쉬운 설명:** 세 가지를 정해야 합니다.
  1. 휴대폰에서 열 주소: Vercel 배포 주소
  2. 웹 앱 주소(`config.js`)를 배포판에 넣는 방법: 지금 `config.js`는 `.gitignore`에 있어서 Git으로 올라가지 않습니다
  3. 앱 화면 파일: `my-feature.html`에 이어서 만들지, `trialnerror/index.html`과 합칠지, 새 파일을 만들지
- **추천:**
  1. Vercel 배포 주소를 쓴다.
  2. **팀과 상의가 필요합니다.** 웹 앱 주소는 결국 브라우저에서 보이는 값이라 API 키만큼 비밀은 아닙니다. 그래서 `config.js`를 커밋해도 되는지 팀이 판단해 주세요. 커밋한다면 질문 5(호출 수 제한)도 함께 생각해야 합니다.
  3. **`my-feature.html`에 이어서 만든다.** 1단계 입력 화면이 이미 여기 있어서, "입력 → 로딩 → 학습 → 완료" 흐름을 한 파일로 이어 가기 가장 쉽습니다. `trialnerror/index.html`은 3단계(카드 표시)를 만들 때 참고만 합니다.
- **이유:** 휴대폰 확인이 모든 단계의 완료 조건이므로, 이걸 먼저 정해야 S2-1부터 확인할 수 있습니다.

### 질문 5. 웹 앱 주소를 아는 사람이 마구 부르면?
- **쉬운 설명:** Apps Script 주소를 아는 사람은 누구나 우리 AI를 부를 수 있습니다. 그러면 무료 한도를 남이 다 써 버릴 수 있습니다.
- **추천: MVP 개발 중에는 그대로 둔다. 실제 사용자 검증(Phase 3) 전에 다시 정한다.**
- **이유:** 결제 카드가 없으면 돈은 나가지 않고, 지금은 팀원만 씁니다. 지금 필요 없는 기능은 만들지 않습니다(YAGNI).
- **상태: Phase 3 전 재검토 (2026-10-27 admin).** S2-3에서는 원문 길이 상한(50,000자)만 넣는다. 시험 중 원인 모를 사용량 초과(`QUOTA`)가 보이면 앞당겨 다시 정한다.

### 질문 7. AI가 앞면이나 뒷면이 빈 카드를 주면?
- **쉬운 설명:** AI가 실수로 빈 카드나 이상한 값을 줄 수 있습니다. 이때 어떤 안내를 띄울지 PRD에 없습니다.
  - (가) "원문을 확인하라" 문구
  - (나) "잠시 후 다시 시도해주세요" 문구
  - (다) 그 카드만 빼고 계속
- **추천: (나) "잠시 후 다시 시도해주세요"**
- **이유:** 빈 카드는 원문 탓이 아니라 AI 실수입니다. PRD 기능 7에도 "원문 탓이 아닌데 '원문을 확인하라'고 하면 헷갈린다"고 적혀 있습니다.

### 질문 8. 문장 수는 어떻게 셀까?
- **쉬운 설명:** "한 면 3문장 이하" 규칙을 검사하려면 문장을 세야 합니다. 지금 코드는 `.` `?` `!` `。`가 나오면 한 문장으로 셉니다. 그래서 "1.5배", "Mr. Kim"처럼 마침표가 문장 끝이 아닐 때 잘못 셀 수 있습니다.
- **추천: 지금의 단순한 규칙으로 시작한다. 테스트하다가 잘못 세는 경우가 실제로 나오면 그때 고친다.**
- **이유:** 미리 복잡하게 만들면 입문자가 읽기 어렵습니다(KISS, YAGNI).

### 질문 9. 원문에 없는 예문을 덧붙인 카드는 규칙 위반일까?
- **쉬운 설명:** 단어 원문(예: "apple - 사과")으로 카드를 만들 때, AI가 "I ate an apple." 같은 예문을 스스로 덧붙일 수 있습니다.
- **추천: 위반으로 본다.**
- **이유:** PRD 3-5는 "원문에 없는 사실·숫자·이름·날짜가 0개"입니다. 예문도 원문에 없는 내용이므로 같은 기준을 적용하는 것이 가장 단순합니다. 카드 생성 지시문(프롬프트)에도 이미 "예문을 덧붙이지 않는다"가 들어 있습니다.

### 질문 10. 실패 기록(개발자용)은 어디에 남길까?
- **쉬운 설명:** 사용자에게는 "잠시 후 다시 시도해주세요"만 보이지만, 개발자는 진짜 이유(키 오류, 시간 초과 등)를 알아야 고칠 수 있습니다.

## C. 실제 사용자가 쓰기 전에 정할 것

### 질문 14. 실제 사용자에게는 무료와 유료 중 무엇으로?
- **쉬운 설명:** 직장인은 회사 자료를 붙여넣을 수 있습니다. 무료 등급이면 그 글을 Google 쪽 사람이 읽을 수 있습니다. 약관에도 "민감한 정보, 기밀, 개인정보는 넣지 말라"고 적혀 있습니다.
  - (가) 유료로 바꾼다: 1회 몇 원~몇십 원. 보낸 글을 AI 개선에 쓰지 않음
  - (나) 무료를 유지하고 경고·동의를 받는다
- **추천: (가) 유료. "팀원이 아닌 사람이 자기 글을 넣기 시작할 때" 바꾼다(조건 1). 결제를 연결할 때 예산 알림을 월 1만 원으로 함께 설정한다.**
- **이유:** 시험 규모(수백 번)에서는 유료로 바꿔도 몇천 원 이하입니다. 경고 문구만으로는 실수를 막을 수 없습니다. 예산 알림이 있으면 예상보다 돈이 나갈 때 바로 알 수 있습니다.

### 질문 15. 입력 화면에 데이터 경고 문구를 넣을까?
- **쉬운 설명:** 예시 문구: "회사 내부 자료·개인정보는 넣지 마세요. 입력한 글은 Google AI로 보내지며, 서비스 개선을 위해 사람이 읽을 수 있습니다." 이 문구는 PRD 화면 설계에 없어서, 넣으면 범위가 늘어납니다.
- **추천: 14번에서 유료를 고르면 넣지 않는다. 무료를 유지한다면 넣는다.** 넣을지는 팀·강사님과 범위를 정한 뒤 결정합니다.
- **이유:** 유료 등급은 보낸 글을 AI 개선에 쓰지 않으므로 이 경고가 맞지 않습니다. 무료라면 사용자가 알고 선택할 수 있어야 합니다.

### 질문 16. 법적으로 괜찮을까?
- **쉬운 설명:** 직장인이 회사 자료나 개인정보를 AI로 보내는 것이 문제가 되는지, 이메일을 저장할 때 개인정보 동의가 필요한지 확인해야 합니다(PRD 10번 #8).
- **추천 답 없음.** 우리가 판단할 수 없습니다. **강사님이나 전문가께 확인**해야 합니다.
- **강사님께 이렇게 여쭤보세요 (예시):**
  > "사용자가 붙여넣은 글을 Gemini API로 보내서 카드를 만듭니다. 무료 등급은 Google이 입력을 학습에 쓰고 사람이 볼 수 있다고 약관에 적혀 있습니다. 실제 사용자 검증(Phase 3) 때 (1) 유료 등급으로 바꾸면 충분한지, (2) 개인정보 수집·이용 동의나 국외 이전 안내가 필요한지, (3) Google 로그인으로 이메일을 저장할 때 어떤 동의가 필요한지 알고 싶습니다."

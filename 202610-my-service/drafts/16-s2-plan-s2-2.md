## 0. 먼저 알아둘 것 (3가지)

1. **검사는 HTML(CODE)에서 한 번만 한다.** Apps Script는 AI가 준 `cards`를 그대로 넘긴다(02 5번, DRY). 그래서 S2-2에서 만든 검사 함수는 S2-4에서 진짜 결과에도 **그대로** 쓴다. 가짜 결과만 S2-4에서 지운다.
2. **`sheet-test.html`의 `checkStack()`은 가져오지 않는다.** 21장 이상을 실패로 보는 v1.4 규칙이다(CLAUDE.md 구조 절). 가져오는 것은 문장 세기 한 줄(`countSentences`)뿐이다.
3. **카드 0장 확인(4-a)은 S2-2에서는 "가짜"로만** 한다. 진짜 AI가 0장을 주는지는 S2-5에서 F-1 원문으로 본다. 04 실패용 "사과"(2자)는 길이 규칙에서 먼저 막혀 4-a 확인에 쓸 수 없다(CLAUDE.md 기준 문서 절).

### 1-2. 왜 이 순서인가

- **1(배열인지)을 맨 앞에:** 배열이 아니면 `.length`·`.slice`를 쓸 수 없어 코드가 멈춘다. 그리고 이건 원문 탓이 아니라 AI·서버 쪽 고장이므로 서비스 문제다.
- **2(0장)를 3(자르기)보다 앞에:** 0장은 자를 것도 없다. 순서를 바꿔도 결과는 같지만, PRD 기능 4 → 기능 5 순서와 맞춰 읽기 쉽게 했다.
- **3(자르기)을 4·5보다 앞에:** 21번째 카드가 비어 있거나 4문장이어도, **어차피 버릴 카드 때문에 전체가 실패하면 안 된다**(02 6-1 "왜 이 순서인가"). 그래서 자른 **뒤에 남은 20장만** 검사한다. → 가짜 `cards-22-bad-tail`로 확인한다(4번 체크리스트).
- **4(형식)를 5(문장 수)보다 앞에:** 앞면이 숫자(`123`)나 없음이면 문장을 셀 때 코드가 멈춘다. 형식이 맞는지 먼저 봐야 문장을 셀 수 있다.
- **4(형식 오류)와 5(문장 수 오류)가 함께 있으면 → 서비스 문제.** 남은 카드 **전체의 형식을 먼저 다 보고**, 모두 맞을 때만 전체의 문장 수를 본다. (팀장 승인, 2026-10-24)
  - 예: 3번 카드가 4문장(원문 문제 감), 7번 카드가 빈 앞면(서비스 문제 감) → **서비스 문제**. 7번의 형식 오류가 먼저 걸리기 때문이다.
  - 이유: 형식이 하나라도 깨졌으면 AI 응답 자체가 고장이다. 이때 "원문을 확인하라"고 하면 사용자가 원문 탓으로 오해한다(PRD 기능 7 이유와 같음). 코드도 반복문 두 개(형식 → 문장 수)라 읽기 쉽고, 둘째 반복문에서는 모든 면이 문자열이라 문장을 셀 때 멈추지 않는다.
  - 비교(고르지 않은 방식): 카드를 1번부터 차례로 보며 한 카드 안에서 두 검사를 함께 하면, 위 예는 3번이 먼저 걸려 **원문 문제**가 된다.
  - → 그래서 위 표 4와 5는 **"남은 카드 전체"** 를 기준으로 쓴 것이다.
  - **확인:** 3-3번 node 확인 ① (휴대폰 가짜는 따로 만들지 않는다). 나중에 "반복문을 하나로 합치는" 정리를 하면 이 규칙이 조용히 바뀔 수 있으니, 그때도 ①을 다시 돌린다.

### 1-3. 문장 세기 (팀 질문 8 결정: 단순 규칙)

- 규칙: `.` `?` `!` `。`가 나오면 문장이 끝난 것으로 본다. 이 기호가 붙어 나오면(`...`, `?!`) 한 번으로 센다. 기호 뒤에 글자가 없으면 빈 조각은 세지 않는다.
- `sheet-test.html`의 `countSentences()` 한 줄을 그대로 가져온다. `my-feature.html`은 화살표 함수(`=>`)를 쓰므로 그 모양으로만 바꾼다.

**알려진 한계 (지금은 고치지 않는다, YAGNI)**

| 예 | 사람이 센 문장 | 코드가 센 문장 | 영향 |
|---|---|---|---|
| `에너지가 1.5배 늘었다.` | 1 | 2 | 더 많게 셈 → 멀쩡한 카드가 "원문 문제"로 실패할 수 있다 |
| `Mr. Kim met Dr. Lee.` | 1 | 3 | 〃 |
| `e.g. apple` | 1 | 2 | 〃 |
| `42.5%` 같은 소수 | — | 1개 더 | 〃. 02 교재·기출 원문(수치가 많음)에서 나올 가능성이 가장 높다 |
| 마침표 없이 줄바꿈으로 나눈 4줄 | 4 | 1 | 더 적게 셈 → 긴 면이 통과할 수 있다 (3-3 사람 확인으로 잡음) |
| 전각 물음표·느낌표 `？` `！` | 1 | 0 또는 이어 붙음 | 더 적게 셈. 일본어·중국어 원문에서 나올 수 있다 |
| 말줄임표 한 글자 `…` (예: `끝…`) | 1 | 1 (`…`를 문장 끝으로 안 셈) | 문장 끝이 `…`뿐이면 앞뒤 문장이 하나로 세어져 더 적게 셈. 한국어 기사 원문(03)에 자주 나온다. 위험은 낮다 |

## 2. 주고받는 값 모양

### 2-1. AI 응답 JSON (02 4·5번과 같음)

```json
{ "cards": [ { "front": "질문", "back": "답" } ] }
```

- Apps Script → HTML은 `{ "ok": true, "cards": [...] }` (02 5번 표). S2-4에서 `requestCards`가 이것을 `{ kind: 'ok', cards }`로 바꿔 돌려준다. **S2-1에서 이미 정한 모양 그대로**라서 S2-2는 이 모양을 바꾸지 않는다.
- 카드에 `front`·`back` 말고 다른 칸이 와도 무시한다(지우지도, 검사하지도 않는다). KISS.

### 2-2. 검사 함수 `checkCards(cards)`

| | 내용 |
|---|---|
| 받는 값 | `cards` — AI가 준 카드 목록. **무엇이 올지 모른다고 가정한다**(배열이 아닐 수도, 숫자가 섞일 수도) |
| 돌려주는 값 (성공) | `{ kind: 'ok', cards: 남은카드 }` — 남은카드는 1~20장, 생성 순서 그대로. `slice`로 만든 **새 목록** |
| 돌려주는 값 (실패) | `{ kind: 'source' }` 또는 `{ kind: 'service' }` — `requestCards`의 실패 모양과 같아서 기존 `showFail(kind)`에 그대로 넘긴다 |
| 하지 않는 것 | 화면 바꾸기, 안내 띄우기, 원문 읽기. **값만 보고 결과만 돌려준다** → 같은 입력이면 항상 같은 결과 (7-b가 구조로 지켜짐) |
| 개발자 기록 | 서비스 문제일 때만 `console.warn`에 **이유 코드와 카드 번호만** 남긴다: `NOT_ARRAY`, `BAD_CARD`(예: `BAD_CARD 2`). **카드 내용·원문은 남기지 않는다**(02 5번, 팀 질문 10 추천과 같은 방향). 원문 문제는 사용자 문구로 충분해서 기록하지 않는다 |

**모양 미리 보기 (S2-2에서 dev가 쓸 코드의 뼈대, 실제 주석은 한·영 함께)**

```js
// 카드 장수·문장 수 규칙 (PRD v1.5 기능 5) / Card rules
const MAX_CARDS = 20;
const MAX_SENTENCES = 3;

// . ? ! 。 기준 문장 세기 (팀 질문 8: 단순 규칙) / Count sentences (simple rule)
function countSentences(text){
  return text.split(/[.?!。]+/).filter((s) => s.trim() !== '').length;
}

// 한 면이 문자열이고 비어 있지 않은지 / Face is a non-empty string
function isGoodFace(face){
  return typeof face === 'string' && !isEmpty(face);   // 기존 isEmpty 재사용 / reuse isEmpty
}

// AI 카드 검사: 형식 → 0장 → 20장 자르기 → 빈 면 → 문장 수
function checkCards(cards){
  if (!Array.isArray(cards)) { console.warn('[Flip] NOT_ARRAY'); return { kind: 'service' }; }
  if (cards.length === 0) return { kind: 'source' };
  const kept = cards.slice(0, MAX_CARDS);              // 앞 20장만, 안내 없음
  for (let i = 0; i < kept.length; i++) {              // 형식 먼저 전부
    const card = kept[i];
    if (!card || !isGoodFace(card.front) || !isGoodFace(card.back)) {
      console.warn('[Flip] BAD_CARD', i + 1);
      return { kind: 'service' };
    }
  }
  for (const card of kept) {                           // 그다음 문장 수 전부
    if (countSentences(card.front) > MAX_SENTENCES || countSentences(card.back) > MAX_SENTENCES) {
      return { kind: 'source' };
    }
  }
  return { kind: 'ok', cards: kept };
}
```

- `isEmpty`(1단계에서 만든 "띄어쓰기·줄바꿈만이면 빈 것")를 **다시 쓴다**(DRY). 빈 입력 규칙과 빈 면 규칙이 같은 기준이 된다.
- `typeof … === 'string'`을 `isEmpty`보다 **먼저** 본다. 숫자에 `.trim()`을 부르면 코드가 멈추기 때문이다.

## 3. `my-feature.html`에서 바꿀 곳

### 3-0. 지킬 스타일 (13 2-0번과 같음)

- 주석은 **한국어 / 영어**를 함께. 색은 `:root` 변수만. `.screen`의 `100dvh`·`env(safe-area-inset-*)`는 건드리지 않는다.
- 새 라이브러리·새 파일 없음. 바꾸는 파일은 `my-feature.html` 하나다.
- 1단계 함수(`isEmpty`, `isKoreanMain`, `measure`, `checkLength`)와 S2-1 함수(`showScreen`, `resetStart`, `showFail`, [확인] 처리)는 **바꾸지 않는다.** `isEmpty`는 읽기만(다시 쓰기만) 한다.

### 3-1. 바꿀 곳 (요소·함수 이름 단위)

| 무엇 | 어디에 | 하는 일 |
|---|---|---|
| 상수 `MAX_CARDS`, `MAX_SENTENCES` | 길이 규칙 상수(`MIN_CHARS`…`MAX_WORDS`) **바로 아래** | 20, 3. PRD 숫자를 한곳에 모은다 |
| `countSentences(text)` | `checkLength` 함수 **바로 아래** ("검사 함수" 묶음) | 1-3번 규칙 |
| `isGoodFace(face)` | 〃 | 2-2번 |
| `checkCards(cards)` | 〃 | 2-2번. 화면을 건드리지 않는다 |
| `handleResult(result)` | 기존 함수 | **맨 앞에 한 줄**: `ok`면 `checkCards`를 거친 결과로 바꾼다. 예: `const checked = result.kind === 'ok' ? checkCards(result.cards) : result;` 그 뒤는 `checked`로 지금과 같이 처리한다(`ok`면 임시 표시, 아니면 `showFail`) |
| 임시 결과 표시 | `handleResult`의 `ok` 부분 | 지금 "카드 N장 받음 (임시)" → **"카드 N장 받음 (임시) · 처음: (첫 카드 앞면) · 끝: (마지막 카드 앞면)"** 으로 늘린다. 5-b에서 "앞 20장이 생성 순서대로"인지 휴대폰에서 보려면 처음·끝이 보여야 한다. 20장 목록 전체는 그리지 않는다(3단계 화면을 미리 만드는 셈, YAGNI. 팀장 승인). `textContent`로 넣는다(카드 글을 HTML로 해석하지 않게). 기존 원 숨기기 줄(`loadingSpinner.hidden = true`)은 그대로 둔다 |
| `.loading-text` | CSS | 위 문구가 375px에서 두 줄로 접히므로 `text-align:center;`와 `overflow-wrap:anywhere;` 두 줄을 더한다. 뒤쪽은 S2-4 뒤 진짜 앞면에 띄어쓰기 없는 긴 영어·주소가 와도 옆으로 넘치지 않게 하려는 것이다. 색·크기는 그대로 |

- **`requestCards`는 검사하지 않는다.** "결과 가져오기"(`requestCards`)와 "결과 검사"(`checkCards`)를 나눠 두면, S2-4에서 `requestCards` 몸통만 진짜 요청으로 바꿔도 검사는 그대로 남는다(역할 나누기).
- 실패 문구는 새로 만들지 않는다. `checkCards`는 `'source'`/`'service'`만 돌려주고, 문구는 기존 `MSG_FAIL` 한 곳에서만 나온다(7-b).
- 실패하면 기존 `showFail` → `resetStart`가 그대로 불린다. 그래서 [확인] 뒤 원문이 남고(7-a), [카드 만들기]를 다시 누를 수 있다. 새로 할 일 없음.

### 3-2. 가짜 장치 넓히기 `[FAKE-S2-2]`

- 주소 끝 `?fake=…`로 고르는 방식은 S2-1과 같다. 기다리는 시간도 같다(2초).
- **한곳에 모은다:** `requestCards` 함수 **바로 위**에 `[FAKE-S2-2]` 덩어리를 하나 둔다. 안에는 "이름 → 가짜 카드 목록" 표(`FAKE_S2_2`) 하나와, 가짜 카드 N장을 만드는 작은 함수(`fakeCards(n)`, `for` 반복문으로 "가짜 질문 1"… "가짜 답 1"…) 하나만 둔다.
  ```
  // [FAKE-S2-2] 시작: 검사 함수 시험용 가짜 AI 결과 (S2-4에서 지움) / Fake AI cards for checkCards (remove in S2-4)
  …
  // [FAKE-S2-2] 끝 / End
  ```
- `requestCards` 안 `[FAKE-S2-1]` 덩어리에는 **한 줄만** 더한다: "`FAKE_S2_2`에 그 이름이 있으면 `{ kind: 'ok', cards: 그 목록 }`을 돌려준다." 즉 가짜 결과는 **AI가 성공(ok)으로 준 것처럼** 들어가고, 검사는 `handleResult` → `checkCards`가 한다. 진짜 흐름과 같은 길로 지나가게 하려는 것이다.

| 주소 끝 | 가짜 AI 결과 | 기대 결과 | 확인할 것 |
|---|---|---|---|
| `?fake=cards-0` | `[]` (0장) | 원문 문제 | 4-a (가짜) |
| `?fake=cards-22` | 22장, "가짜 질문 1"~"가짜 질문 22" | 성공, 20장 | 5-b |
| `?fake=cards-22-bad-tail` | 22장, **21번째 뒷면이 `첫째. 둘째. 셋째. 넷째.`(4문장), 22번째 앞면이 `""`(빈칸)** | 성공, 20장 (실패 아님) | 1-2번 "자르기 먼저" |
| `?fake=sentences-3` | 3장, 2번째 뒷면이 정확히 3문장 (`첫째. 둘째. 셋째.`) | 성공, 3장 | **3문장 경계 (통과해야 함)** — PRD 3-3 자체는 S2-5에서 진짜 카드를 직접 셈 |
| `?fake=sentences-4` | 3장, 2번째 뒷면이 `첫째. 둘째. 셋째. 넷째.` (4문장) | 원문 문제, 카드 표시 없음 | 5-a |
| `?fake=empty-front` | 3장, 2번째 앞면이 `""` | 서비스 문제 | 팀 질문 7 |
| `?fake=blank-back` | 3장, 2번째 뒷면이 띄어쓰기·줄바꿈만 | 서비스 문제 | 팀 질문 7 (공백만 = 빈 것) |
| `?fake=number-front` | 3장, 2번째 앞면이 숫자 `123` | 서비스 문제 (코드가 멈추지 않음) | 팀 질문 7, 2-2번 순서 |
| `?fake=not-array` | `cards`가 목록이 아니라 글자 `"cards"` | 서비스 문제 | 1-1번 표 1 |
| (그대로) `?fake=ok`, `slow`, `fail-*` | S2-1과 같음 | S2-1과 같음 | 회귀 확인 (`ok` 3장도 이제 검사를 거쳐 통과해야 함) |

- 일부러 **2번째 카드**를 망가뜨린다. 첫 카드만 보는 실수(반복문을 한 번만 도는 버그)를 잡기 위해서다.
- 4문장 글은 기호가 분명한 `첫째. 둘째. 셋째. 넷째.`로 고정한다. "1.5"처럼 1-3번 한계에 걸리는 글을 쓰면 엉뚱한 이유로 통과하거나 실패할 수 있기 때문이다. (node로 4가 나오는 것을 검토 담당이 확인함)
- 철자가 틀리면(예: `cards-2`) S2-1과 같이 **가짜 성공 3장**이 나온다(13 2-2 G-3 주의). 기대와 다르면 주소 철자부터 본다.
- **지우는 때와 방법 (13 2-2번 그대로):**
  - S2-4에서 `[FAKE-S2-1]`과 함께 `[FAKE-S2-2]` 덩어리를 지운다. 지우기 **전에** 이 덩어리를 `drafts/fake-responses.md`에 옮겨 둔다(PRD 5-b는 가짜 결과로 확인하므로, 검사 함수를 고칠 때 다시 쓸 수 있게).
  - S2-4 커밋 전 `my-feature.html`에서 `fake`를 **대소문자 무시**로 검색해 **0줄**인지 본다: `git grep -i fake -- 202610-my-service/my-feature.html`. 대문자 `FAKE`만 찾으면 `const fake`, `fakeCards` 같은 소문자 이름이 남아도 못 찾는다. (S2-4 계획 체크리스트에 넣는다 → 9번 메모)
  - **`checkCards`·`countSentences`·`isGoodFace`·상수·임시 표시는 지우지 않는다.** 진짜 결과에도 쓰는 코드다. (임시 표시는 3단계 학습 화면이 생길 때 바뀐다)
- 이 기간에도 Vercel 주소를 팀 밖에 공유하지 않는다(13 2-2 주의 그대로).

## 4. 휴대폰 확인 체크리스트 (S2-2)

번호는 **PRD 완료 조건** 번호다. 원문은 아무 원문이나 길이 규칙만 통과하면 된다(예: T03). 가짜 결과는 원문 내용과 상관없다.

**모든 줄 공통 순서 (한 줄 볼 때마다 매번)**
1. 주소 끝 `?fake=` 뒤를 바꿔서 **새로 연다.** 성공(`ok`) 뒤에는 로딩 화면에 머물러 있어서, 다음 가짜를 보려면 꼭 새로 열어야 한다.
   - 휴대폰에서 주소 끝 고치는 법: 주소창을 탭 → 글자 맨 끝으로 커서 이동 → `?fake=` 뒤 글자만 지우고 새 이름을 쓴 뒤 이동.
2. 새로 열면 입력창이 비므로 **T03 원문을 다시 붙여넣는다.** (원문을 휴대폰 메모장에 복사해 두면 빠르다)
3. [카드 만들기]를 누르고 2초 기다린다.

| 완료 조건 | 이렇게 해 보기 | 이렇게 되면 통과 |
|---|---|---|
| 4-a (가짜) | `?fake=cards-0`로 열고 원문을 넣어 [카드 만들기] | 로딩 뒤 "카드를 만들지 못했습니다. 원문을 확인한 후 다시 시도해주세요"가 **글자 그대로** 보인다 |
| 5-a | `?fake=sentences-4` | "카드 N장 받음"이 **보이지 않고**, 원문 문제 문구가 보인다 |
| (3문장 경계, 통과해야 함) | `?fake=sentences-3` | "카드 3장 받음 (임시)"가 보인다. PRD 3-3 자체는 S2-5에서 진짜 카드로 직접 센다 |
| 5-b | `?fake=cards-22` | "카드 **20**장 받음 (임시) · 처음: 가짜 질문 1 · 끝: 가짜 질문 **20**". 안내 문구(잘랐다는 말)는 **없다** |
| 5-b (자르기 먼저) | `?fake=cards-22-bad-tail` | 위와 똑같이 "카드 20장 받음 … 끝: 가짜 질문 20". 실패 안내가 **뜨지 않는다** |
| (팀 질문 7) | `?fake=empty-front`, `blank-back`, `number-front`, `not-array`를 하나씩 | 네 경우 모두 "잠시 후 다시 시도해주세요". 로딩 화면에 멈춰 있지 않는다 |
| 7-a | 위 실패 중 아무거나에서 [확인] | 안내가 사라지고 입력창에 원문이 그대로 있다. [카드 만들기]를 다시 누를 수 있다 |
| 7-b | `?fake=sentences-4`와 `?fake=cards-0`을 각각 두 번 / `empty-front`와 `?fake=fail-service`를 각각 한 번 | 원문 문제 4번이 모두 같은 문구, 서비스 문제 2번이 모두 같은 문구다 |
| (S2-1 다시 확인) | `?fake=ok`, `?fake=slow`, `?fake=fail-source` | S2-1과 같이 동작한다. `ok`는 "카드 3장 받음 (임시) · 처음: 가짜 질문 1 · 끝: 가짜 질문 3" |
| (1단계 다시 확인) | 빈 입력, 9자 넣기 | 기존 길이 안내가 뜨고 로딩으로 넘어가지 않는다 |
| (화면) | 375px 휴대폰에서 `cards-22` 결과 보기 | 임시 문구가 화면 밖으로 넘치지 않고 줄바꿈되어 다 보인다 |
| (개발자 기록, 선택) | PC 브라우저에서 `?fake=empty-front` 후 개발자 도구 콘솔 보기 | `[Flip] BAD_CARD 2`만 보이고 카드 내용·원문은 없다 |

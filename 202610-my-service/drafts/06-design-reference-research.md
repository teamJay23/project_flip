## 2. 화면별 정리

표 읽는 법: 각 사례마다 **가져올 점 / 버릴 점 / 우리 화면 어디에 쓸지** 3줄. PRD와 부딪히는 것은 "**참고 제외**"로 표시했다.

### A. 입력 화면 (텍스트 붙여넣기 → [카드 만들기])

| 참고 사례 | 가져올 점 | 버릴 점 | 우리 화면 어디에 쓸지 |
|---|---|---|---|
| Quizlet (세트 만들기) | 만들 대상(세트)을 먼저 정하고 시작하는 단순한 흐름 | 앞면·뒷면을 한 칸씩 사람이 직접 입력하는 방식 (우리는 AI가 만듦) | 입력창 위 한 줄 안내: "공부할 글을 붙여넣으세요" |
| 뉴닉 (주제 소개) | "오늘 꼭 알아야 할 소식만"처럼 **무엇을 하면 되는지 한 줄로** 말하는 문구 | 오디오 브리핑, 커뮤니티 기능 (**참고 제외**: 범위 밖) | 입력창의 placeholder(빈 칸에 흐리게 보이는 안내 글) 문구 |
| Anki (카드 추가) | — (우리와 방식이 달라 가져올 것이 적음) | 필드·덱·태그를 고르는 복잡한 입력 (**참고 제외**: 폴더·template 여러 개는 범위 밖) | 쓰지 않음 |

- PRD 지킬 것: [카드 만들기] 버튼은 **입력창 아래**(2-1). 길이 안내·실패 안내는 **입력 화면 위**에 띄운다(3-1 화면 구조). 입력창 글자를 자르지 않는다(기능 1 규칙).

### B. 로딩 화면

| 참고 사례 | 가져올 점 | 버릴 점 | 우리 화면 어디에 쓸지 |
|---|---|---|---|
| 듀오링고 (애니메이션) | 기다리는 동안 **움직이는 작은 그림**으로 "멈춘 게 아니다"를 보여 줌. 공개 글에 따르면 움직임은 짧고(0.2~0.5초 단위) 아껴 쓴다 (비공식 정리, 확인 필요) | 캐릭터(마스코트) 제작은 시간이 많이 든다 | 카드가 뒤집히는 짧은 반복 애니메이션 1개 + "카드를 만들고 있어요" 문구 |
| Anki | — (로딩 화면이 없음) | — | 쓰지 않음 |

- PRD 지킬 것: 로딩 중 사용자가 할 수 있는 행동 없음(기능 6). **"몇 % 남음" 같은 진행 막대는 참고 제외**(진행도 표시는 범위 밖, 실제 진행률도 알 수 없음). 60초가 지나면 실패 안내로 간다.

### C. 학습 화면 (카드 뒤집기, 안다/모른다, 한 손 엄지 영역)

> **한 손 엄지 영역**: 휴대폰을 한 손으로 쥐었을 때 엄지가 편하게 닿는 곳. 보통 **화면 아래쪽 절반**이다. 위쪽 구석은 닿기 어렵다.

| 참고 사례 | 가져올 점 | 버릴 점 | 우리 화면 어디에 쓸지 |
|---|---|---|---|
| Anki | **카드 아무 데나 탭하면 답이 보인다** (우리 6-1과 같음). 답 버튼이 화면 **아래쪽**에 있어 엄지가 닿는다. | ① 버튼 4개(Again/Hard/Good/Easy) → **참고 제외** (우리는 2개). ② 화면 아래 남은 카드 수 3개 → **참고 제외** (진행도 표시는 범위 밖). ③ 카드 좌우를 탭해서 답을 고르는 방식 → **참고 제외** (우리는 카드 탭 = 뒤집기만, 6-2) | 카드 전체를 탭 영역으로. 안다/모른다는 카드 **바깥**에 둔다 |
| Quizlet | **두 갈래 이름**: "Know / Still learning". "모른다"보다 부드러운 이름이 부담을 줄인다 (우리 "모름 · 애매"와 같은 생각) | 학습 진행 막대, Learn 모드 퀴즈 → **참고 제외** (진행도·퀴즈는 범위 밖) | 버튼 문구 확인: "← 알고 있음" / "모름 · 애매 →" (PRD 문구 그대로) |
| Flippy | 스와이프 하나로 분류하는 빠른 흐름 (2차 스와이프 참고) | **방향이 반대** (Flippy: 알면 오른쪽 / 우리 PRD: 안다 = 왼쪽 ←). 그대로 따라 하면 안 됨 | 2차 단계(스와이프) 때 "얼마나 밀어야 인정하는지" 참고 |
| 클래스카드 | "한 손으로 넘기며 외우기"를 앞세움 → 우리 자투리 시간 사용자와 같은 상황 | 테스트·목표 점수 기능 → **참고 제외** (범위 밖) | 모든 버튼을 엄지 영역(화면 아래 절반)에 둔다는 원칙 |

- PRD 지킬 것:
  - 카드 탭 = **뒤집기만** (6-2). 다음 카드로 넘기지 않는다.
  - "← 알고 있음"은 **카드 왼쪽 바깥**, "모름 · 애매 →"는 **카드 오른쪽 바깥** (7-1, 8-1). 앞면·뒷면 둘 다 보인다.
  - **[이전]/[다음(스킵)] 버튼 없음**, **진행도 없음**, **라운드 바뀜 표시 없음** → 다른 앱에 있어도 참고 제외.
- 주의할 점 (팀 논의 필요): "카드 왼쪽·오른쪽 바깥" 텍스트가 카드 옆에 붙으면 카드가 좁아지고, 화면 가운데 높이에 있으면 엄지가 닿기 어렵다. **카드 바로 아래 좌우 양 끝**에 두면 PRD의 "왼쪽/오른쪽 바깥"도 지키고 엄지 영역에도 들어온다. 이 해석이 PRD와 맞는지 팀이 정한다.

### D. 완료 화면 ([다시 학습] / [새로 만들기])

| 참고 사례 | 가져올 점 | 버릴 점 | 우리 화면 어디에 쓸지 |
|---|---|---|---|
| 듀오링고 (레슨 완료) | 끝났다는 것을 **짧은 축하 메시지 + 아래쪽 큰 버튼**으로 분명히 보여 줌 | XP·정확도·속도 숫자, 연속 학습일(streak) → **참고 제외** (통계·진행도·저장은 범위 밖이고, Phase 3 검증용 기능을 미리 만들지 않음) | 완료 메시지 1줄(10-4) + 아래쪽에 [다시 학습] / [새로 만들기] 두 버튼(10-5) |
| Anki (오늘 학습 끝) | 끝났을 때 더 할 일이 없다는 것을 분명히 알림 | 다음 복습 일정 안내 → **참고 제외** (간격 반복·저장은 범위 밖) | 메시지 문구 참고만 |

- PRD 지킬 것: 완료 화면에 메시지와 두 버튼 말고 더 보여 줄 정보는 "만들면서 확인할 것"(PRD 7번). 지금은 넣지 않는다.

### (+) 가이드 카드 목록 화면 (**MVP 범위 안**, 강사님 승인. PRD 반영 전)

| 참고 사례 | 가져올 점 | 버릴 점 | 우리 화면 어디에 쓸지 |
|---|---|---|---|
| 뉴닉 | 주제(시사·경제·테크)별로 짧은 요약을 고르는 구조. 리뷰상 "스토리처럼 넘겨 보던 1분 뉴스"를 좋아한 사용자가 있었음 | 긴 목록형 배치 (리뷰에서 가독성 불만) | 카테고리 탭 4개(시사 / AI / 스포츠 / 경제 용어) + 탭마다 카드 10장을 가로로 넘겨 보기 |
| 다음 뉴스 (구독형 개편 보도) | 탭 3개처럼 **탭 수를 적게** 유지 | 구독·추천 알고리즘 → **참고 제외** (로그인 연동·개인화는 범위 밖) | 카테고리 탭은 4개 이하로 |
| 네이버 뉴스 | 카테고리별 묶음 | 언론사 구독, 댓글 → **참고 제외** | 쓰지 않음 (2026년 화면 확인 못 함) |

- 가이드 카드 1장 구성 제안 (위에서 아래로):
  1. 카테고리 표시 (작은 글씨, 예: "경제 용어")
  2. 제목 (굵게, 예: "투자자 예탁금")
  3. 원문 앞 2줄 미리보기
  4. [이 글로 카드 만들기] 버튼
  5. **출처 한 줄: 카드 맨 아래, 작은 이탤릭** (admin 결정). 형식 `출처: 매체명 (나라), 기사 날짜`. 예: *출처: Korea Herald (한국), 2026-10-23*
- 출처 줄 스타일 제안: 글자 크기 12px 정도, 이탤릭, 색은 보조 글자 `--ink-soft`. 버튼보다 아래에 두어 누르는 영역과 겹치지 않게 한다.
- 주의: Pretendard는 한글 이탤릭 글꼴이 따로 없어 브라우저가 글자를 비스듬히 기울여 보여 준다. 휴대폰에서 읽기 괜찮은지 확인이 필요하다.
- 출처 줄은 **화면에만** 보이고, [이 글로 카드 만들기]를 눌렀을 때 입력창에는 들어가지 않는다. 입력창에 들어가면 AI가 출처로 학습 카드를 만들 수 있기 때문이다.
- [이 글로 카드 만들기]를 누르면 **입력 화면 A의 입력창에 원문이 채워지고**, 사용자가 [카드 만들기]를 직접 누른다(기존 흐름을 바꾸지 않기 위해).
- 어디서 보여 줄지(입력 화면 아래? 별도 화면?)는 화면 수가 4개(A~D)에서 늘어나는 문제라 팀이 정한다.

## 3. PRD 충돌로 "참고 제외"한 것 한눈에 보기

| 디자인 요소 | 본 앱 | 왜 제외 | PRD 근거 |
|---|---|---|---|
| 진행 막대, 남은 카드 수 | Anki, Quizlet | 진행도 표시는 이번 버전에서 뺌 | 기능 13 |
| 버튼 3~4개 (Hard/Easy 등) | Anki | 선택지는 안다/모른다 2개 | 기능 11·12 |
| 카드 탭으로 답 고르기 | Anki | 카드 탭은 뒤집기만 | 6-2 |
| [이전]/[다음(스킵)] 버튼 | 여러 앱 | 만들지 않음 | 3번 범위 |
| 라운드 바뀜 표시 | — | 표시 없음으로 시작 | 기능 14 |
| XP, 정확도, 연속 학습일 | 듀오링고 | 통계는 Phase 3 이후, 범위 밖 | CLAUDE.md "지금 단계" |
| 간격 반복 일정 (10m, 5d) | Anki | 저장·이어하기는 범위 밖 | 3번 범위 |
| 폴더, 덱, 즐겨찾기, my library | Anki, Quizlet | 범위 밖 | 3번 범위 |
| 퀴즈·테스트 모드 | Quizlet, 클래스카드 | 범위 밖 | 3번 범위 |
| 구독·추천·댓글 | 네이버·다음 | 범위 밖 | 3번 범위 |
| 오른쪽 = 안다 스와이프 | Flippy | 우리는 왼쪽(←) = 안다 | 기능 11 |
| 이메일 가입, 카카오·네이버 로그인 | 여러 앱 | v1.5는 **Google 로그인만** 범위 안 | 3번 범위, 기능 18 |

> 참고: 팀장 지시에는 "로그인 = 범위 밖"으로 적혀 있었지만, **PRD v1.5에서는 Google 로그인(기능 18, E 화면)이 범위 안으로 들어왔다.** 그래서 [Google로 로그인] 버튼 하나짜리 화면은 참고해도 되고, 그 밖의 로그인 방식만 제외했다.

## 4. 디자인 결정 제안 (결정은 팀이 한다)

1. **색**: 지금 `:root` 변수를 그대로 쓴다. 배경 `--paper`(#faf6ef), 글자 `--ink`(#2a2138) / 보조 글자 `--ink-soft`, 강조·[카드 만들기] 버튼 `--amber`(#f2b84b), **"← 알고 있음" = `--know`(#9cb380 초록)**, **"모름 · 애매 →" = `--review`(#e36b6b 빨강)**. Anki도 Again 빨강 / Good 초록이라 사용자에게 익숙한 조합이다. 새 색은 만들지 않는다.
2. **폰트**: Pretendard 한 가지. 카드 글자는 18px 이상, 안내 문구는 14px 이상으로 해서 지하철에서도 읽히게 한다(숫자는 제안, 휴대폰에서 확인 후 조정).
3. **버튼 배치**: 안다/모른다는 **카드 바로 아래, 왼쪽 끝과 오른쪽 끝**에 둔다(엄지 영역 + PRD의 "왼쪽/오른쪽 바깥"). 누르는 영역은 손가락 크기를 생각해 높이 44px 이상. [카드 만들기], [다시 학습]/[새로 만들기]도 화면 아래쪽에 둔다.
4. **카드 크기**: 화면 너비 375~430px 기준으로 좌우 여백을 두고 너비 약 85~90%, 세로는 화면의 약 절반. 한 면 3문장이 글자 넘침 없이 들어가는지(5-3, 6-3) 가장 긴 테스트 카드로 확인한다.
5. **움직임**: 카드 뒤집기 애니메이션 하나만 쓴다. 로딩 화면에서도 같은 뒤집기 모양을 반복해 앱 전체 느낌을 맞춘다.

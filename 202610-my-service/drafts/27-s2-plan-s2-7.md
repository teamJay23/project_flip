## 1. 바꿀 것 (`my-feature.html`만)

02 계획 6-2번 설계 그대로, 지금 구조(`AbortController` 하나로 "먼저 온 것 하나만" 처리)를 바꾸지 않고 더한다.

1. 진행 중인 요청을 기억하는 변수 1개: `pending = { controller, startedAt, timer }` (요청이 없으면 `null`)
2. `requestCards`에서 `startedAt = Date.now()`를 기록하고, 끝나면(`finally`) `pending = null`
3. `visibilitychange` 받기 — 화면이 다시 보이고(`visible`) 요청이 진행 중일 때만:
   - 지난 시간 ≥ 60초 → `controller.abort()` → 기존 `catch`의 `TIMEOUT` 길로 "서비스 문제" (6-c)
   - 지난 시간 < 60초 → 타이머를 지우고 **남은 시간**으로 다시 건다 (멈춘 타이머가 늦게 울리지 않게)
4. 결과가 화면 뒤에서 도착하면 → 지금처럼 바로 반영 (6-a, 고칠 것 없음)

```js
// 진행 중인 요청 (없으면 null) / Request in progress
let pending = null;

// 화면이 다시 보이면 지난 시간으로 60초를 다시 판단 (02 6-2번)
// When the page is visible again, re-check the 60s limit by wall-clock time
document.addEventListener('visibilitychange', () => {
  if (document.visibilityState !== 'visible' || !pending) return;
  const left = LOAD_TIMEOUT_MS - (Date.now() - pending.startedAt);
  const c = pending.controller;                       // 이 요청의 것만 끊기 / Only this request
  clearTimeout(pending.timer);
  if (left <= 0) c.abort();                           // 6-c
  else pending.timer = setTimeout(() => c.abort(), left);
});

// requestCards 안: 처음 타이머도 pending.timer에 넣고, finally에서 pending.timer를 지운 뒤 pending = null
// Inside requestCards: store the first timer in pending.timer; finally clears pending.timer, then pending = null
```

- (reviewer 막음 1, 2026-10-31) 다시 건 타이머가 옛 `pending`이 아니라 **그 요청의 controller**를 잡아야 한다. 안 그러면 실패 안내 → [확인] → 바로 다시 누른 **다음 요청**이 60초 전에 끊긴다. 그래서 `finally`도 지역 `timer`가 아니라 `pending.timer`를 지운다

- 늘어나는 줄: 약 15줄. 실패 문구·실패 나누기(6-1번 표 0~5)는 그대로
- 함께 정할 것: 돌아와 보니 **요청이 끊겨 있으면** (휴대폰이 요청을 끊음, 인터넷은 켜짐) → 지금 코드는 `FETCH_FAILED` → "잠시 후 다시 시도해주세요" (팀 질문 13, admin 결정 필요)

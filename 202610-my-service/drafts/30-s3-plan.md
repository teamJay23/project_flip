### S3-1. 학습 화면 + 첫 카드 앞면 (4-1, 4-2, 5-1, 5-3)

1. **화면 C 추가**: `<main class="screen study-screen" id="studyScreen" hidden>`. 기존 `.screen`(100dvh, 안전 영역 패딩)을 **그대로** 쓰므로 iOS 처리가 깨지지 않는다.
2. **`showScreen`에 `'study'` 추가**: 한 줄 더함 (`studyScreen.hidden = name !== 'study';`).
3. **메모리에 기억할 값 3개** (새로고침하면 사라짐 — 4-3은 "이후" 단계):
   - `stack` = 카드 배열 / `current` = 지금 카드 번호(0부터) / `isFlipped` = 뒷면을 보고 있는지
4. **`handleResult` 성공 길**: 임시 글자·`loadingSpinner.hidden = true` 두 줄을 지우고 `startStudy(checked.cards)` 호출.
5. **같은 질문 거르기** (결정 1): 앞뒤 띄어쓰기를 뺀 앞면 글자가 **완전히 같으면** 뒤에 나온 카드를 버린다. 안내 없음 (20장 자르기와 같은 방식). 거르는 **순서**는 결정 6:
   - (A) 20장 자른 **뒤** 거르기 (아래 코드처럼 `startStudy`에서): `checkCards`를 안 고침. 단, AI가 21장 이상 + 중복을 주면 19장이 되어 PRD 5-b "앞 20장"과 어긋날 수 있다 (드묾)
   - (B) 20장 자르기 **전** 거르기 (**추천**): `checkCards` 289줄을 `const kept = dedupeFronts(cards).slice(0, MAX_CARDS);`로 한 줄 바꿈. 형식 검사 전이므로 `dedupeFronts`는 앞면이 글자가 아닌 카드는 거르지 않고 남겨 둔다(그 뒤 형식 검사가 "서비스 문제"로 잡음) — 1줄 더함. 이 경우 `startStudy`는 `stack = cards`
6. **글자는 `textContent`로 넣는다** (`innerHTML` 금지). = AI가 준 글을 "글자"로만 넣어, 글 속 `<태그>`가 화면 코드로 실행되지 않게 함.
7. **긴 글 처리 (5-3)**: 카드는 남은 높이를 채우고(`flex:1`), 면 안에서 세로 스크롤(`overflow-y:auto`). 카드와 각 면에 **`min-height:0`**을 꼭 넣는다 (reviewer 주의 2) — 없으면 flex 안의 상자가 글 길이만큼 늘어나 스크롤이 생기지 않고 화면 밖으로 밀려난다. `overflow:hidden`(잘라서 숨김)은 쓰지 않는다. 짧은 글은 가운데로 보이게 `margin:auto`를 쓴다 — `justify-content:center`는 글이 넘칠 때 **위쪽이 잘려 스크롤로도 못 보는** 문제가 있어서 쓰지 않는다. 긴 영어 단어는 `overflow-wrap:anywhere`.
8. **글자**: Pretendard 18px, 줄 간격 1.6, **왼쪽 정렬**(3문장 답이 읽기 쉬움, 19번 4절).
9. **버튼 자리** (결정 2, reviewer 주의 1): 버튼은 4단계에 만들지만, 카드 크기가 버튼 위치에 따라 달라지므로 **3단계 배치는 admin 선택을 따른다.** 4단계에서 카드 크기가 안 바뀌어야 5-3·6-3을 다시 잴 필요가 줄어든다.
   - ① 카드 옆 (PRD 글자 그대로 "카드 왼쪽·오른쪽 바깥"): 카드 좌우에 각 56px + 간격 8px **빈 칸**. 375px에서 카드 너비 약 **215px**(한 줄 약 11자) → 긴 글이 길어져 스크롤이 더 자주 생김
   - ② 카드 아래 좌우 끝 (19번 추천안): 카드 아래 높이 52px **빈 줄**. 카드 너비 **343px**(375px 기준)

```js
// 학습 상태 (메모리에만, 새로고침하면 사라짐) / Study state, memory only
let stack = [];
let current = 0;
let isFlipped = false;

// 같은 질문은 처음 것만 남김 (PRD 4-2) / Keep only the first card of each question
function dedupeFronts(cards){
  const seen = new Set();
  return cards.filter((card) => {
    if (!card || !isGoodFace(card.front)) return true; // 형식 검사가 잡게 남김 (안 B) / Leave for format check
    const key = card.front.trim();
    if (seen.has(key)) return false;
    seen.add(key);
    return true;
  });
}

// 학습 시작: 첫 카드 앞면 (PRD 4-1, 5-1) / Start study on first card's front
function startStudy(cards){
  stack = cards; // 안 A면 dedupeFronts(cards) / Option A: dedupe here
  showCard(0);
  showScreen('study');
  cardEl.focus();
}

// 카드 하나 보이기, 언제나 앞면부터 (5-1, 4단계 5-2 준비) / Show a card, always front first
function showCard(i){
  current = i;
  frontText.textContent = stack[i].front;
  backText.textContent = stack[i].back;
  frontFace.scrollTop = 0; // 새 카드는 맨 위부터 (reviewer 참고 6) / New card starts at top
  backFace.scrollTop = 0;
  setFlipped(false);
}
```

### S3-2. 탭해서 뒤집기 (6-1, 6-2, 6-3)

1. **카드 전체가 탭 영역**: `<div class="card" id="card" role="button" tabindex="0">` 안에 앞면·뒷면 두 장을 겹쳐 둔다. `<button>` 대신 `div`인 이유: 버튼 안에서는 긴 글 스크롤이 브라우저마다 다르게 동작할 수 있어서.
2. **탭 = 뒤집기만** (6-2): 클릭에서 `setFlipped(!isFlipped)`만 부른다. `current`는 절대 안 바꾼다. 뒷면에서 다시 탭하면 앞면 (결정 3, PRD 7번 "만들면서 확인할 것").
3. **뒤집기 연출** (결정 3): 옛 프로토타입의 Y축 회전(`perspective`, `rotateY(180deg)`, `backface-visibility:hidden` + `-webkit-` 앞붙임)을 0.4초로. "동작 줄이기" 설정이면 회전 없이 바로 바뀜 (`prefers-reduced-motion`, 로딩 원과 같은 규칙).
4. **두 번 탭 확대 막기**: 카드에 `touch-action: manipulation`.
5. **안 보이는 면 막기** (reviewer 주의 3): 겹쳐 있는 안 보이는 면에 `pointer-events:none`(손가락 입력을 받지 않음)을 준다. 안 그러면 뒷면을 밀었는데 뒤에 숨은 앞면이 스크롤될 수 있다. 회전이 끝난 뒤에는 `visibility:hidden`도 함께 (회전 중에는 보여야 하므로 `transition`에 지연을 둠).
   - **대비책**: Whale에서 회전 중 면이 비치거나 스크롤이 엉키면, "동작 줄이기" 길(회전 없이 바로 바꾸기)을 **기본**으로 바꾼다. 코드는 CSS 몇 줄만 바뀐다.
6. **스크롤 뒤 손을 뗄 때 뒤집힐지** (결정 7): 보통 브라우저는 밀기(스크롤)를 탭으로 보지 않지만, 스크롤이 미끄러지는 중에 손가락으로 멈추면 탭으로 잡힐 수 있다. 안:
   - (가) 그대로 둠 — 코드 없음. ④에서 실제로 잘못 뒤집히는지 보고 정함
   - (나) 손가락을 댄 위치에서 **10px 넘게 움직였거나 그 사이 `scrollTop`이 바뀌었으면** 그 탭은 무시 — `pointerdown`에서 위치·`scrollTop` 기억, `click`에서 비교 (약 10줄)
   - 추천: **(가)로 시작, ④에서 잘못 뒤집히면 (나)**
7. **접근성 기본**: `role="button"` + `tabindex="0"` + Enter/Space 키로도 뒤집기. 안 보이는 면은 `aria-hidden="true"` → 화면 읽기 기능이 보이는 면만 읽음. 화면 C가 뜨면 카드에 포커스(`:focus-visible`일 때만 테두리).
8. **색**: 뒷면 바탕 `--back`(`#2a1b42`, 옛 프로토타입 값)을 `:root`에 추가, 글자 `--amber`. 앞면 `--paper` + `--ink`. 대비 8.8 / 14.2 (19번 4-2절).
9. **"질문" / "답" 작은 표시** (결정 4): 면 왼쪽 위에 13px. 색을 잘 구분하지 못해도 앞뒤를 안다.

```js
// 앞/뒤 바꾸기만, 다음 카드로 가지 않음 (PRD 6-2) / Flip only, never move on
function setFlipped(flipped){
  isFlipped = flipped;
  cardEl.classList.toggle('flipped', flipped);
  frontFace.setAttribute('aria-hidden', String(flipped));
  backFace.setAttribute('aria-hidden', String(!flipped));
  // pointer-events·visibility는 CSS가 .flipped를 보고 처리 / CSS handles pointer-events and visibility via .flipped
}
cardEl.addEventListener('click', () => setFlipped(!isFlipped));
cardEl.addEventListener('keydown', (e) => {
  if (e.key === 'Enter' || e.key === ' ') { e.preventDefault(); setFlipped(!isFlipped); }
});
```

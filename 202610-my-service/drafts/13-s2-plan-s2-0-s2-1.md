   - 이번 계획에서는 **파일 이름을 하나씩 지정해서** `git add`한다.

### 1-1. admin이 직접 할 일 (키를 다루는 일은 admin만)

> **주의: 키 값(`AQ.…` 또는 `AIza…`로 시작하는 긴 글자. 2026-10-27 확인: 우리 키는 `AQ.`)은 Claude·ChatGPT 같은 AI 채팅, 카톡, 메모 앱, 코드 파일 어디에도 붙여넣지 않는다.**
> 키 값을 붙여넣는 곳은 **딱 한 곳**, 아래 ③의 Apps Script 스크립트 속성 칸뿐이다. AI 도구에는 이름 `GEMINI_API_KEY`만 알려 준다.
> 실수로 붙여넣었다면 AI Studio에서 그 키를 **삭제하고 새로 발급**한다.

메뉴 이름은 2026-10-24에 직접 화면을 보고 확인한 것이 아니다. 그래서 각 단계에 **(확인 필요)** 를 붙였다. 화면이 다르면 비슷한 이름을 찾고, 다르게 생긴 점을 팀에 알려 준다.

**① Google AI Studio에서 키 발급**
1. https://aistudio.google.com 에 Google 계정으로 들어간다.
2. 왼쪽 메뉴 또는 오른쪽 위에서 **"Get API key"(API 키 가져오기)** 를 누른다. (확인 필요)
3. **"API 키 만들기"(Create API key)** 를 누른다. Google Cloud 프로젝트를 고르라고 하면 새 프로젝트를 만들거나 기존 것을 고른다. (확인 필요)
4. 만들어진 키는 **복사만 해 두고 어디에도 붙여넣지 않는다.** 바로 ③으로 간다.
5. **결제(Billing)는 연결하지 않는다.** (02 계획 3-2번 결정: 무료 등급 유지)
6. AI Studio에서 무료 등급의 사용 한도(분당·하루 호출 수)가 보이면 숫자를 적어 둔다. 02 계획과 08 계획에서 "확인 필요"로 남아 있는 값이다. (메뉴 위치 확인 필요)

**② 키 사용 범위 제한 (새어 나가도 다른 데 못 쓰게)**
1. https://console.cloud.google.com 에 들어가 ①에서 고른 프로젝트를 선택한다.
2. **"API 및 서비스" → "사용자 인증 정보"(Credentials)** 로 간다. (확인 필요)
3. 목록에서 방금 만든 API 키를 누른다.
4. **"API 제한사항" → "키 제한"** 을 고르고, 목록에서 **"Generative Language API"** 하나만 체크한 뒤 저장한다. (확인 필요)
   - "애플리케이션 제한사항"은 고르지 않는다. Apps Script 서버에서 부르기 때문에 웹사이트 제한을 걸면 오히려 막힐 수 있다.

**③ 새 Apps Script 프로젝트 + 스크립트 속성**
1. https://script.google.com 에서 **"새 프로젝트"** 를 누른다. 기존 `Code.gs`(저장 시험) 프로젝트와 **다른 새 프로젝트**다.
2. 프로젝트 이름을 `flip-card-api`로 바꾼다(왼쪽 위 "제목 없는 프로젝트"를 누름).

4. 속성 이름에 `GEMINI_API_KEY`를 쓰고, 값에 ①의 키를 붙여넣고, **"스크립트 속성 저장"** 을 누른다.

### 1-6. S2-3로 넘길 메모 (v1.2, 이번 범위는 아님)

- **키는 주소가 아니라 헤더로 보낸다.**
  - Gemini를 부를 때 키를 주소 끝(`?key=…`)에 붙이면, `UrlFetchApp`이 실패했을 때 오류 메시지에 **주소 전체(키 포함)** 가 들어갈 수 있다.
  - 그 오류를 `console.log`하면 Apps Script 실행 기록에 키가 남는다.
  - 그래서 키는 요청 헤더(주소가 아니라 요청에 따로 붙는 정보 칸)로 보낸다. 헤더 이름은 `x-goog-api-key`로 알려져 있고, S2-3에서 Gemini 공식 문서로 다시 확인한다.
- **실행 기록에는 오류 메시지 전체를 남기지 않는다.** `reason`(KEY/QUOTA/…)과 상태 코드만 남긴다 (02 계획 5번과 같음).
- **임시 `doGet`은 지운다** (1-1 ④).
- **배포는 "배포 관리 → 새 버전"으로** 하고, 다시 나오는 권한 승인 화면에서 승인한다 (1-1 ④ 6).

### 1-7. S2-4로 넘길 메모 (15 코드 검토 G-4, 2026-10-24)

- 지금 클릭 처리기는 `await requestCards()`를 `try/catch` 없이 부른다. S2-1 가짜 코드는 오류를 던지지 않아서 지금은 문제가 없다.

**JavaScript**

| 무엇 | 이름 | 하는 일 |
|---|---|---|
| 실패 문구 상수 | `MSG_FAIL` | `{ source: '카드를 만들지 못했습니다. 원문을 확인한 후 다시 시도해주세요', network: '인터넷 연결을 확인한 뒤 다시 시도해주세요', service: '잠시 후 다시 시도해주세요' }` — PRD 기능 7 문구를 **글자 그대로** |
| 화면 전환 | `showScreen(name)` | `'input'` / `'loading'` 중 하나만 보이게 한다. 지금 `inputScreen.hidden`·`nextScreen.hidden`을 직접 바꾸는 두 줄을 이 함수로 옮긴다 |
| 실패 안내 보이기 | `showFail(kind)` | `failText.textContent = MSG_FAIL[kind]` → `showScreen('input')` → `failLayer.hidden = false` → **`resetStart()`** → `failOkBtn.focus()`([확인]에 바로 손이 가게) |
| 시작 되돌리기 | `resetStart()` | `isStarted = false; submitBtn.disabled = false;` — 지금은 한 번 시작하면 다시 못 누르는 문제를 고친다 (02 1-2 주의) |
| [확인] 누르기 | `failOkBtn` 클릭 | `failLayer.hidden = true` → `submitBtn.focus()`. **입력창 원문은 건드리지 않는다**(7-a). 입력창에 포커스를 두면 휴대폰 키보드가 올라오므로 [카드 만들기] 버튼에 둔다 |

| 제출 | `submitBtn` 클릭 (기존) | 기존 두 번 누름 막기(`isStarted`)와 길이 검사(`checkLength`)는 **그대로**. 통과 뒤 `showScreen('loading')` → `requestCards` → `handleResult` 순서로 바꾼다 |

- 기존 `isEmpty`, `isKoreanMain`, `measure`, `checkLength`, 입력 시 안내 숨기기는 **바꾸지 않는다.**
- S2-1 범위 밖: 60초 시간 초과, 다른 앱 갔다 오기(`visibilitychange`), 인터넷 끊김 실제 감지. 이것들은 S2-4·S2-7에서 한다.

### 2-2. 가짜 결과로 시험하는 방법

- 주소 끝에 **`?fake=…`** 를 붙여 결과를 고른다. 예: `…/my-feature.html?fake=fail-source`

| 주소 끝 | 가짜 결과 | 기다리는 시간 | 확인할 것 |
|---|---|---|---|
| (없음) 또는 `?fake=ok` | 성공, 카드 3장 | 2초 | 로딩 → "카드 3장 받음 (임시)" |
| `?fake=slow` | 성공 | 8초 | 로딩 화면이 8초 동안 계속 보이는지 (6-b) |
| `?fake=fail-source` | 원문 문제 | 2초 | 문구가 글자 그대로인지 (7-b) |
| `?fake=fail-network` | 인터넷 | 2초 | 〃 |
| `?fake=fail-service` | 서비스 문제 | 2초 | 〃 |

- 읽는 법: `new URLSearchParams(location.search).get('fake')` (주소 끝 값을 읽는 브라우저 기본 명령)
- 주의: **철자가 틀리면(예: `?fake=fail-sorce`) 가짜 성공이 나온다.** 실패 안내를 기대했는데 "카드 3장 받음 (임시)"가 보이면 주소 철자부터 확인한다. (15 코드 검토 G-3)
- **가짜 코드는 한곳에 모은다.** `requestCards` 안의 한 덩어리를 아래 주석으로 감싼다.
  ```
  // [FAKE-S2-1] 시작: 가짜 결과 (S2-4에서 지움) / Fake results (remove in S2-4)
  …
  // [FAKE-S2-1] 끝 / End
  ```
- **지우는 방법과 시점:**
  - S2-4(진짜 Apps Script 연결)에서 이 덩어리를 진짜 요청 코드로 **바꿔 넣는다.**
  - S2-4를 커밋하기 전에 `my-feature.html`에서 `FAKE`를 검색해 **0줄**인지 확인한다. (S2-4 실행 계획 문서의 체크리스트에 이 줄을 넣는다. 02 계획 8번 휴대폰 체크리스트에는 아직 없다)
  - S2-2(검사 함수)용 22장·4문장 가짜 응답도 같은 표시(`[FAKE-S2-2]`)로 모으고 같은 때 지운다.
  - **단, S2-2 가짜 응답 JSON은 버리지 않는다.** PRD 5-b는 "가짜 AI 결과로 확인한다"라서, 검사 함수를 고칠 때마다 다시 시험할 수 있어야 한다. 그래서 지우기 전에 JSON을 `drafts/` 아래 문서(예: `drafts/fake-responses.md`)에 남겨 두고, 다시 시험할 때만 잠깐 붙였다가 뗀다. (다른 방법인 "코드에 남기고 콘솔에서만 부르기"보다 단순해서 이쪽을 고름, KISS)
- 주의: S2-1~S2-3 동안 Vercel 배포판에서도 `?fake=`가 동작한다. 파라미터가 없으면 기본이 "가짜 성공"이라 "카드 3장 받음 (임시)"만 나온다.
  - 그래서 이 기간에는 **팀 밖 사람에게 Vercel 주소를 공유하지 않는다.**
  - Phase 3 전에는 반드시 지워진다.

## 3. PRD·문서와 맞지 않는 점 (참고)

- 고지 문구는 아직 **PRD에 없다** (02 3-4번 "PRD 수정 필요"). S2-1에서 넣기 전에 PRD에 규칙을 더하거나, "PRD 반영 전 임시"로 넣을지 정해야 한다 → 팀 질문 5.
- `CLAUDE.md` 구조 절에는 "`config.js` — `.gitignore`로 커밋에서 제외"라고 아직 적혀 있다(35줄). 반면 보안 절(56줄)은 "커밋한다"이다. S2-0 뒤에 구조 절도 고쳐야 한다 (팀장 담당).

## 4. 팀이 정할 것 (이 문서 관련)

1. 저장소 맨 위 `.gitignore`에 `.env` 말고도 개인 폴더(`Career/`, `Memos/`, `.obsidian/` 등)를 넣을지
2. **(admin 선택, S2-0 안에서)** 저장 시험(`Code.gs`) 주소를 어떻게 막을지: (가) 저장 시험 웹 앱 배포를 "배포 관리 → 보관"한다 / (나) `config.js`에는 새 카드 생성 주소만 넣는다(추천) / (가)+(나) (1-3번). 저장 시험을 계속 쓰려면 그 주소를 커밋하지 않는 별도 파일에 둔다. 그리고 `202610-my-service/.gitignore`가 비면 파일을 지울지도 정한다
3. 카드 생성 Apps Script 코드의 **사본을 저장소에 둘지** (예: `202610-my-service/card-api.gs`). 두면 코드 기록이 남는다. 두지 않으면 Apps Script 편집기에만 있다. 키는 어느 쪽이든 코드에 없다
4. `my-feature.html`을 Vercel 첫 화면으로 쓰려고 `index.html`로 바꿀지, 주소 끝 `/my-feature.html`을 쓸지
5. 고지 문구를 PRD에 먼저 반영할지, S2-1에 "PRD 반영 전 임시"로 먼저 넣을지 (02 팀 질문 18)

## [꼭 고칠 것]

### K-1. `config.js` 커밋 순서와 점검에 빈틈이 있다 → 저장 시험 주소가 공개 기록에 남을 수 있다

- 근거:
  - 13 1-2번 dev 할 일 표의 순서는 다음과 같다.
    - #2 "`202610-my-service\.gitignore`에서 `config.js` 줄 빼기"
    - #3 "`config.js` 내용을 카드 생성 주소로 바꾸기"
  - 지금 `config.js`에는 저장 시험(`Code.gs`) 웹 앱 주소가 들어 있다. 그 웹 앱은 "모든 사용자" 권한으로 `doGet`(승인 줄을 누구에게나 돌려줌)과 `doPost`(누구나 시트에 씀)를 연다. 13 0번 1에 이 내용이 정확히 적혀 있다.
  - 저장소는 **공개**다(`CLAUDE.md` 36줄). 13 0번 3은 아직 "공개인지 비공개인지 확인 필요"라고 적혀 있다 → 갱신이 필요하다.
  - 13 1-2-1 "커밋 전 점검"은 `AIza`(키)만 검색한다. **옛 주소가 들어갔는지는 보지 않는다.** 그 점검은 1-5 체크리스트 0-6에만 있고, 0-6은 커밋 뒤에 보는 표에 있다.
- 왜 문제인가:
  - #2를 먼저 하면, `config.js`가 "추적 안 됨" 파일로 `git status`에 나타난다. 그 상태에서 #3 전에 `git add`하면 옛 주소가 커밋된다.
  - 예: dev가 #2를 끝내고 중간 저장 커밋을 하는 경우, 또는 다른 작업 커밋에 함께 들어가는 경우.
  - 공개 저장소에 한 번 올라간 주소는 파일을 고쳐도 기록에 남는다. 지우려면 Git 기록 다시 쓰기(입문자에게 어렵고 위험)나 웹 앱 배포 보관이 필요하다.
- 고치는 방법 (작은 수정 3개):
  1. dev 할 일 순서를 **#3(내용 바꾸기) → 확인 → #2(`.gitignore`에서 빼기)** 로 바꾼다. 같은 커밋 하나에 넣는다.
  2. 1-2-1 "커밋 전 점검"에 한 줄을 더한다:
     - "`git diff --cached -- 202610-my-service/config.js`를 열어 **`CARD_API_URL` 한 줄만** 있는지 본다."
     - "옛 저장 시험 주소의 `/macros/s/` 뒤 앞 6글자로 `git diff --cached | grep`해서 0줄인지 본다."
     - 주소 전체를 문서·채팅에 적지 않고 앞 몇 글자만 쓴다.
  3. 0번 3의 "공개 여부 확인 필요"를 "**공개 저장소** (CLAUDE.md 2026-10-24)"로 고친다. 그러면 1-3번 위험 설명이 "커밋하면 GitHub에서 누구나 본다"로 확정된다.
- 참고: 팀 질문 2에서 (가) "저장 시험 주소를 커밋하지 않는 별도 파일에 둔다"를 고른다면, **그 파일 이름을 `.gitignore`에 먼저 적은 뒤** 파일을 만든다. PRD 6-1의 `.env` 규칙과 같은 순서다.
